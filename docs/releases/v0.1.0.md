# Niyah.Engine v0.1.0

`v0.1.0` is the first packaged release of Niyah.Engine. It freezes the current native C11 research runtime and its verified CPU-facing build, training, evaluation, persistence, and inference surfaces without expanding the project into a hosted service or general-purpose assistant claim.

## Included

- native C11 autoregressive Transformer runtime;
- deterministic byte-level BPE tokenizer and tokenizer-bound dataset shards;
- fresh training and checkpoint/resume with AdamW state and dataset cursor persistence;
- CPU FP32 inference with KV-cache decoding and greedy/seeded stochastic sampling;
- optional CUDA source-build backend;
- read-only `niyah eval` with model loss/perplexity and add-1 bigram baseline;
- loss-mask-aware supervised V3 evaluation with matching baseline geometry;
- model-only checkpoint loading for inference/evaluation while preserving checkpoint integrity checks;
- diagnostic `niyah_probe` surface;
- blind external human-evaluation pack;
- CMake install rules for the static library, public headers, and primary CLI tools;
- CPack-based Linux TGZ and Windows ZIP packaging;
- reproducible CPU release workflow with SHA-256 manifests and extracted-package `niyah --help` smoke tests.

## Primary command surfaces

```text
niyah prepare
niyah eval
niyah run
niyah-train new
niyah-train resume
niyah_probe
```

## Verification boundary

The release gate requires:

- Ubuntu Release build/tests;
- Windows MSVC Release build/tests;
- ASan/UBSan tests;
- Linux and Windows install/package smoke tests;
- extracted Linux and Windows package execution of `niyah --help`;
- SHA-256 checksum generation for release archives.

A local workstation verification was reproduced at repository revision `f3e218c5c024723e305b43447631e551141cedb3` before release packaging work: Windows Release 30/30, WSL Release 30/30, and WSL ASan/UBSan 30/30 with a clean worktree.

The published release artifacts were then rebuilt and verified by the release workflow on exact `main` commit `f6fda8df219cb090c48b0b0587352d053bb464b5`. Linux packaging, Windows packaging, extracted-package smoke tests, ASan/UBSan, and the combined checksum bundle all passed. Only after those gates succeeded did the workflow create `v0.1.0` at that same commit and publish the already-verified artifacts. No separate tag-triggered workflow run is claimed.

## Release payload

CPU release archives contain:

```text
bin/
  niyah
  niyah-train
  niyah_probe
lib/
  libniyah.a or niyah.lib
include/
  niyah/*.h
share/doc/NiyahEngine/
  LICENSE
  README.md
```

Platform-specific suffixes and archive structure are determined by the release toolchain.

The release does **not** include datasets, training corpora, checkpoints, pretrained model weights, test fixtures, or development-only build products.
